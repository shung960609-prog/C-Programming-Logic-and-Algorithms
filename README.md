# C/C++ 核心邏輯與演算法實作 (Core Concepts & OOP)

本專案收錄了我在大一期間的 C/C++ 核心練習。我不僅要求程式能跑出正確結果，更注重過程中的邏輯推演、記憶體管理與演算法效能比較。以下為精選的實作紀錄與反思：

## 💡 精選技術反思 (Technical Insights)

### 1. 演算法思維：遞迴 (Recursion) vs. 迴圈 (Iteration)
* **原始碼：** `sequence_recursion_vs_iteration.c`
* **開發心得：** 
針對特定數列計算（第4項後為前三項之和），我深入思考了兩種解法。**遞迴法**寫起來直覺，但我學到了必須嚴謹設定 `n=1, 2, 3` 的終止條件（Base Case），否則會造成無窮迴圈或 Stack Overflow。**迴圈法**雖然程式碼較長，但透過 `t1, t2, t3` 三個變數的推移（Sliding window 概念），可以更有效率地算出答案，這讓我深刻體會到演算法中「邊界條件」與「效能優化」的重要性。

### 2. 資料型態與機率模擬 (Monte Carlo Simulation)
* **原始碼：** `monte_carlo_dice_simulation.c`
* **開發心得：** 
在實作千萬次擲骰子賭局期望值模擬時，面對高達 10,000,000 次的累加運算，我意識到使用 `int` 會產生溢位 (Overflow)，因此改用 `long long` 來處理大數據。此外，直覺上看似有賠率優勢的規則，經過大量模擬後總金額卻幾乎為負，這次實作讓我學會如何用程式來嚴謹驗證機率與數學期望值。

### 3. 模組化設計與程式碼重用 (Code Reusability)
* **原始碼：** `gcd_lcm_calculator.c`
* **開發心得：** 
在撰寫最大公因數 (GCD) 時，我練習了暴力搜尋法與迴圈條件判斷。而在實作最小公倍數 (LCM) 時，我意識到不需要重新寫一個複雜的迴圈，而是直接運用數學公式 `LCM = (a*b) / GCD`，在 LCM 函式中直接呼叫剛剛寫好的 GCD 函式。這讓我體會到「程式碼重用」與「模組化設計」對維持程式碼簡潔的好處。

### 4. 系統化思維：跨足物件導向 (OOP)
* **原始碼：** `geometry_oop_classes.cpp`
* **開發心得：** 
從 C 跨足到 C++，我開發了幾何圖形運算系統，利用 C++ 的 Class 語法，分別建立不同立體圖形的獨立物件，並實作計算體積與表面積的方法。透過實作，我深刻理解了「封裝 (Encapsulation)」的價值——藉由區分 `private` 與 `public`，我學會如何保護物件狀態並提高程式碼的安全性與擴充性。
