# C/C++ 核心邏輯與演算法實作

本專案收錄了我在大一期間的 C/C++ 練習的心路歷程。我要求程式能跑出正確結果，注重過程中的邏輯推演、記憶體管理與演算法效能比較。以下為幾個令我印象最深刻的實作與反思：

## 精選技術反思

### 1. 演算法思維：遞迴 vs. 迴圈
* **原始碼：** `sequence_recursion_vs_iteration.c`
* **反思與心得：** 
針對特定數列計算（第4項後為前三項之和），我深入思考了兩種解法。**遞迴法**寫起來直覺，但我學到了必須嚴謹設定 `n=1, 2, 3` 的終止條件，否則會造成無窮迴圈或 Stack Overflow。**迴圈法**雖然程式碼較長，但透過 `t1, t2, t3` 三個變數的推移，可以更有效率地算出答案，這讓我深刻體會到演算法中邊界條件還有效能優化的重要性。

### 2. 資料型態與機率模擬
* **原始碼：** `monte_carlo_dice_simulation.c`
* **反思與心得：** 
這是在上課時教授提到rand()與迴圈時我連想到的一個擲骰子賭局期望值模擬，在實作千萬次擲骰子賭局期望值模擬時，高達 10000000 次的累加運算，我意識到使用 `int` 會產生溢位，因此改用 `long long` 來處理大量的數據。直覺上看起來有賠率優勢的規則，但經過多次模擬後總金額幾乎為負，這次實作讓我學會如何用程式來嚴謹驗證機率與數學期望值，也完成我上課自己腦中好奇的一支程式。

### 3. 模組化設計與程式碼重用
* **原始碼：** `gcd_lcm_calculator.c`
* **反思與心得：** 
在撰寫最大公因數時，我練習了暴力搜尋法和迴圈條件判斷。而在實作最小公倍數時，我發覺不需要重新寫一個複雜的迴圈，可以直接運用數學公式 `LCM = (a*b) / GCD`，在 LCM 函式中直接呼叫剛剛寫好的 GCD 函式。我發現到程式碼重用和模組化設計對維持程式碼簡潔的好處。

### 4. 跨足物件導向
* **原始碼：** `geometry_oop_classes.cpp`
* **反思與心得：** 
從 C 跨越到 C++，我開發了幾何圖形運算系統，利用 C++ 的 Class 語法，建立不同立體圖形的獨立物件，並且實作計算體積、表面積的方法。透過實作，我深刻理解了封裝的價值，藉由區分 `private` 和 `public`，我學會如何保護物件狀態，提高程式碼的安全性和擴充性。
